# 每日新闻简报 — 国内新闻源停更修复设计

日期：2026-08-17

## 背景与问题

每日新闻推送系统的「国内新闻」长期停留在 2025-06-05，而「国际新闻」一直正常更新。经实测排查，根因是脚本 `daily_news.py` 中配置的 3 个国内 RSS 源全部失效或停更：

| 源 | 状态 | 实测结果 |
|---|---|---|
| 新华网-时政 | 死源 | HTTP 200，内容停在 2022-12-14（废弃 3 年） |
| 人民网-时政 | 停更 | HTTP 200，最新内容停在 2025-06-05 |
| 环球网 | 失效 | HTTP 404 |

## 根因

1. **源已废弃**：三个国内 RSS 源均已停止更新，feedparser 仍能解析出旧条目。
2. **兜底逻辑 bug**（`fetch_all_news`）：网页抓取兜底（澎湃/新浪）仅在国内条目数 `< 5` 时触发，但死源旧闻足以撑满条数，导致兜底永不触发，国内新闻永远循环播放旧闻。
3. **国际源不受影响**：BBC / 德国之声 / FT 中文网跑在 GitHub Actions 境外环境，可正常抓取最新内容。

## 方案

只修改 `daily-news/daily_news.py` 一个文件，其余（工作流 `news.yml`、`config.json`、推送逻辑、KEYWORDS 打分、推送条数）不动。

### 1. 替换国内 RSS 源

在 `RSS_SOURCES` 列表中删除三个死源，替换为中国新闻网的两个活源（实测 2026-08-17 当天实时更新）：

```python
{"name": "中国新闻网-滚动", "url": "https://www.chinanews.com.cn/rss/scroll-news.xml", "category": "国内"},
{"name": "中国新闻网-要闻", "url": "https://www.chinanews.com.cn/rss/china.xml", "category": "国内"},
```

国际源保持不变。

### 2. 新增日期过滤

在 `fetch_rss` 中解析 `entry.published_parsed`（feedparser 自动将 `<pubDate>` 转为时间），丢弃超过 48 小时的条目。目的：任何源未来再次停更时，旧闻在源头即被过滤，不会污染推送。

- RSS 源：按 `published_parsed` 判断，超 48h 丢弃；缺失日期字段的条目保留（避免误伤无日期源）。
- 网页抓取源（`fetch_web`）：无可靠日期字段，视为当天新鲜内容，不参与过滤。

### 3. 修复兜底逻辑

日期过滤发生在「抓取之后、统计条数之前」，使 `domestic_n` 只反映真实新鲜数量，原 `if domestic_n < 5` 的兜底判断随之恢复正确语义，无需改动判断条件本身。

## 验证方式

1. 本地安装依赖（`feedparser` / `requests` / `beautifulsoup4`）后运行脚本，观察抓取与筛选日志：确认中新网两源能抓到当天新闻、旧闻被过滤。
2. `config.json` 中 SendKey 为占位符，本地运行推送会失败，但抓取/筛选日志已足以验证。
3. 确认无误后 push 到 GitHub，用 `workflow_dispatch` 手动触发一次核对推送内容。

## 不做的事（YAGNI）

- 不改每日推送条数（`max_items`）。
- 不改国际源。
- 不改 KEYWORDS 打分与推送格式。
- 不加 dry-run 开关（本地运行 + 日志已足够验证）。
